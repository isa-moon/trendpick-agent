# 数据来源与取数

原则：**能用数据就不用记忆**。每条结论都要能回到一个链接和一个日期。下面的工具都是可选的加速器；缺哪个就用下一个替代，并在交付物的「数据说明」里写明用了什么、缺了什么。

## §0 开始前：检查工具

| 工具 | 怎么判断有没有 | 没有时怎么装 | 装不了时 |
|---|---|---|---|
| 蓝优选热点话题 MCP（国内必需） | 可用工具里有 `query_hot_topics_v2` 或 `query_hot_topics` | 从蓝优选 skill 市场（https://blueai-skills-market.bluemediagroup.cn ，需登录）安装 `hot-topics-data`，按它的说明配置。Key 是蓝优选工具箱通用的 `blueai-` 开头的 Key，申请入口 https://bmc-model-openapi.bluemediagroup.cn/console/dashboard 。配置后要重启 Agent | 用 §1「备选」 |
| KOX（海外推荐） | 命令行能运行 `kox --version` | 登录 KOX 平台（中国大陆 https://maxlauncher.cn ，其他地区 https://maxlauncher.io ），左侧导航栏「KOX SKILL」→「安装 KOX Skill」，复制命令粘贴给 Agent，安装和鉴权一起完成。需要 Python 3.10+。没有团队或团队不对，找所在事业群的 AIBP | 不做视频脉搏，只用 §3 的 X 热门、年度事件页和新闻，交付物里写明 |

- 缺工具时，在对齐需求那一轮里一起说：缺什么、影响什么、怎么装。用户不回答就用备选方案继续做，不要停下来等
- 检查时只看工具列表和命令的返回值，**不要打印或读取 MCP 配置文件的原文**，里面有 Key
- MCP 配置了、但工具列表里没有（配置后还没重启，或你是作为子 Agent 运行的）：请用户重启 Agent 或在主会话里跑，不要自己从配置文件读 Key 去直连。用户不在场就用备选，交付物里写明
- Key 和 token 由用户自己提供。不要回显到对话，不要写进台账、memory 或任何项目文件。KOX 的安装命令里带个人 token，让用户从平台复制，不要代拼

## §1 国内热榜

### 首选：蓝优选热点话题 MCP（hot-topics-data）

覆盖：抖音（总榜、剧情榜）、微博热搜、B站全站日榜、知乎热榜。平台 ID：抖音 1、B站 3、微博 5、知乎 8（**没有 2**，传错会返回 400）。

取数方式：
- **按自然周拆分查询**，取当月至今 + **前两周作为基线**。基线必须有，否则所有梗都像是"本月 1 号才冒头"。
- **加 `export_format: "excel"`**：返回下载链接，不把几千条 JSON 灌进对话。一周四个平台约 3500–3900 条，一个月约 1.4 万条。
- 下载到工作目录，交给 `scripts/trend_stage.py` 处理。

数据特性（会影响判断）：
- 条目是**话题**，不是帖子；`热点链接`是平台搜索页，不是某条内容。它能证明"这个话题哪天上过榜"，可以当梗和数据的出处；但不能当参考内容，参考内容要用具体内容页
- 平台字段可能是「哔哩哔哩」，脚本统一显示为「B站」
- `热度值`单位是"万"，**各平台口径不同，不能跨平台比较**；脚本里一律换算成平台内当日名次
- 每天凌晨采集，**只能查到昨天**；交付物里写"数据截至 X 月 X 日"
- 单个标题寿命极短，见 `judgment.md` §3

### 备选

没有 MCP 时：
1. 网页检索各平台热榜聚合页（如今日热榜 tophub、微博热搜榜），或直接搜「<年>年<月>月 热梗」「最近爆火的 XX 梗」类盘点文章
2. 请用户粘贴截图或导出表
3. 交付物里注明：数据来自检索或用户提供，没有逐日曲线，生命周期只能粗判

### 关键词趋势（可选）

aily-keyword-trend（百度指数 + 抖音热度）可以补一个梗的搜索曲线，适合核对阶段。长尾词、非中文词效果差，延迟约 1 天。

## §2 用 trend_stage.py

```bash
# 总览：按跨平台数、上榜天数排序，先看全月有什么
python3 scripts/trend_stage.py data/*.xlsx --top 80

# 关键词筛选：和品牌、品类、季节相关的条目（单个标题不给阶段，只用来找线索）
python3 scripts/trend_stage.py data/*.xlsx --grep "<品类词>|<原料>|<季节词>|<节日>" --top 120

# 梗级聚类：每个梗一组正则，输出逐日曲线和初判阶段（可重复传多个 --cluster）
python3 scripts/trend_stage.py data/*.xlsx \
  --cluster "某句式=XX刺客" \
  --cluster "品牌自身=<品牌>|<子品牌>|<明星产品>" \
  --show 30 --json out/clusters.json
```

- 支持 xlsx（热点 MCP 的导出）、JSON（MCP 原始返回）、同名列的 CSV
- `--asof` 指定"今天"；默认取数据里最晚的上榜日
- 初判只看曲线，**你要复核**：查看代表条目有没有误命中，结合饱和度和品牌状态修正阶段
- 正则默认不区分大小写；全是大写的拉丁词（`NOVA|诺瓦`，虚构示意）自动区分大小写，避免命中 Innovation。大小写混写的品牌名用 `(?-i:NovaFit)`
- `--show N` 控制每簇显示多少条代表条目（默认 8，`--show 0` 显示全部），查误命中时调大
- `--json` 输出里每簇是 `{cluster, regex, stage, hits, days_on, first, last, idle_days, platforms, daily, weekly, steady, examples}`；`weekly[0]` 是最近 7 天，`steady` 为 true 表示可能是常驻说法
- 总共不到 5 条的簇标「样本不足」；连续 5 周以上平稳出现的簇会打 ⚠「可能是常驻说法」；节日、大促、节气按日期排期，不看脚本给的阶段（`judgment.md` §3）

**怎么发现梗**：总览模式按标题排序，梗不会自己冒出来。两种办法：

```bash
# 1) 让脚本找：多天、多个不同标题里反复出现的开头/结尾片段，且集中在某两周爆发
python3 scripts/trend_stage.py data/*.xlsx --patterns --top 40
```
- 「尾」片段多是**句式梗**（如「…XX 刺客」「…XX 自由」），优先看
- 「头」片段多是**人名、剧名、赛事名**，它们也集中爆发，但属于文娱或新闻，按 `judgment.md` §2 分类
- 「中」片段（`--patterns --middle`）统计标题中间的词，大部分是人名、剧名、产品名，只作补充
- **慢热、平稳的生活方式梗（如「纯 X」）会被 14 天爆发度过滤掉**，`--patterns` 找不到。用总览或 `--grep` 看标题时留意反复出现的说法，再用 `--cluster` 量化
- 新闻套话（如何评价、回应、道歉）全程均匀分布，已被 14 天爆发度过滤掉

2) 自己找：从 `--grep` 的结果里找重复的句式。找到后都用 `--cluster` 量化，并检查代表条目有没有误命中。

## §3 海外热点

海外没有统一热榜接口，靠检索拼出全貌。**每个热点至少要有 2 个独立来源，且日期在本次窗口内**。品牌自己的事实（新车、工厂、展厅）可以只有 1 个来源，但要标「需品牌确认」。

**海外找梗的路径**：
1. 全球梗：Know Your Meme 近期条目、欧美媒体的"本周 TikTok 趋势"盘点
2. 拿到候选后，用 KOX 按国家检索验证当地有没有真命中（`video_pulse.py`）。当地 0 命中的，进跳过表，写"当地无信号"
3. 本地梗：当地媒体的盘点文章、X 当地热门里的非新闻标签

**找不到梗不是失败**。海外梗的验证成本高，常见结果是"本窗口没有能过 2 个来源的梗"。这时只出节点和季节选题，在开头的结论里写明"本次没有可借的梗，以下都是节点"，不要拿没验证的梗凑数。

**先看大环境**（`judgment.md` §1.5）：抓一下 Wikipedia「<年> in <国家>」这类年度事件页，看当月有没有战争、袭击、灾难、外交冲突。这一步决定整份方案的情绪底色，比找梗更优先。

| 要找什么 | 去哪里找 |
|---|---|
| 当地 TikTok 热门标签、音乐、创作者 | TikTok Creative Center（Trend Discovery，可按国家筛选） |
| 当地搜索趋势 | Google Trends（按国家，近 30 天） |
| X 当地热门话题 | trends24.in（按国家或城市） |
| 梗的起源与含义 | Know Your Meme；当地媒体的盘点文章 |
| 节点与大事件 | 当地主流媒体、官方活动网站（节日、展会、赛事、季节性活动） |

**实测可用性**（Claude Code 环境，2026 年秋）：
- WebSearch 工具在部分模型上不可用（报 `tool type ... not supported`）；用 WebFetch 访问 Bing 可能被定位到其他地区，DuckDuckGo 会出人机验证。**不要卡在搜索上**，直接用下面能用的源
- **trends24.in/<国家>/**（如 `/united-arab-emirates/`、`/saudi-arabia/`）用 WebFetch 能拿到 X 近 24 小时的热门话题，按小时分组。注意：中东的 X 热门以政治、宗教、足球为主，多数要进跳过表
- **Wikipedia 年度事件页**能拿到，适合查大环境和节点日期；标了 citation needed 的条目要写【需复核】
- TikTok Creative Center、Google Trends 需要登录或有反爬，能打开就用，打不开就在数据说明里写明

检索时要用**当地语言 + 英语**两套关键词（例如阿拉伯语和英语），只搜英语会漏掉大量本地内容。

海外市场的节点通常比梗更可靠，也更适合品牌：日期已知、调性安全、窗口可以倒推。先列出窗口期内的节点，再找梗。

## §4 样板内容、饱和度与达人（可选）

| 用途 | 国内 | 海外 |
|---|---|---|
| 这个梗有没有真实的爆款内容 | blueai-social-media-data 关键词搜帖子（T+1）；blueai-universal-crawler 搜抖音、B站 | KOX `search-video --query "<梗或标签>" --locations "AE,SA" --days 30 --sort views` |
| 已有多少品牌做过（饱和度） | 同上，搜「梗 + 品类」，统计蓝 V 和品牌号的数量 | 同上，看结果里品牌账号和带货内容的占比 |
| 没有上面的付费工具时 | 看热榜簇里有没有品牌、平台、电商条目，卡片上写上线前人工自查（`judgment.md` §3） | KOX 结果里品牌号的占比 |
| 谁适合拍 | douyin-kol-discovery | KOX `search-video` 找发过同类内容的达人；完整 brief 用 kox-recommend |
| 竞品合作过哪些达人 | — | KOX `query --type brand` |

海外视频脉搏（代替逐日曲线）：

```bash
kox search-video --platform tiktok --query "back to school" --locations "AE,SA" \
    --days 30 --sort views --page-size 20 --format json > raw/back_to_school.json
python3 scripts/video_pulse.py raw/*.json --asof <今天> \
    --must "back_to_school=backtoschool|schoolsupplies"   # 描述里出现这些词才算真命中
```
输出每个话题的「命中/返回」、播放中位数、按周的发布分布、品牌号占比和头部视频链接。

注意：
- **KOX 视频搜索是相关度排序，不是精确匹配**。实测节日名、活动名、「中国车」这类检索，20 条里常常只有 0–3 条真相关，其余是不相干的热门视频。**命中率本身就是信号**：命中低说明这个话题在 TikTok 上没那么大，或者大家不用这个说法。一定看「命中/返回」，不要看返回条数
- **阿拉伯语等非拉丁文字检索基本返回 0 条**，用英语词或带下划线的标签写法（如 `riyadhseason`）；阿语内容仍会被英语标签搜到
- 品牌词会被拆词（「<品牌> 01」→ 品牌 + 01），查品牌自身时用 `--must` 收紧
- 结果按播放取一页，发布分布反映的是头部内容，不是全量
- KOX 默认按作者去重（`unique_author`），「命中/返回」统计的是**作者数**，不是视频数
- `--must` 的键是文件名去掉扩展名，要和文件名完全一致。拉丁字母按词边界匹配：`cat` 不会命中 `catch`，`tank` 不会命中 `thank`；但 `cat` 仍会命中 `cat eye`，要更严就写成词组（`black cat`）或 `#标签`（只匹配标签）。同形词（如 jaguar 既是动物，也是车名）脚本分不出来，要看头部视频人工剔除
- 阿语内容被系统性低估：KOX 阿语检索返回空。沙特、海湾的本地声量请本地团队补充，或者用 X 的阿语搜索、Snapchat 当地内容核对
- KOX 一次只搜**一个**关键词，不支持 OR；N 个方向就跑 N 次
- KOX 输出的表格要原样转述，不改数字、不只挑几行
- 达人推荐是选题之后的下一步。用户没要求时，只在卡片上写「适合的达人类型」，并询问是否需要查具体名单
