# 选题台账

台账让这个 skill 越用越懂某个品牌：哪些梗推过、用户选了什么、拒绝了什么、上线后效果如何。

## 位置

一个品牌一个文件：`<台账目录>/<品牌>.md`，默认 `~/Documents/选题台账/`。第一次使用时，把位置放进对齐需求那一轮问题里一起问（附默认值）；用户不答就用默认位置，并写进「我替你拍的板」。团队共用的话建议放共享盘或 Git 仓库。

## 格式

文件开头是**品牌档案**（会被反复读，保持精简，随时更新）：

```markdown
# <品牌> 选题台账

## 品牌档案
- 市场与受众：
- 调性禁区（用户明确说过的）：
- 偏好（从历次选择中观察到的，注明出处日期）：
- 上线周期：从定题到发布通常 <N> 天
- 已知雷区：<例：YYYY-MM 排队慢被骂，等待/效率相关话题慎用>
```

之后每次运行追加一节，**只追加，不改历史**：

```markdown
## <YYYY-MM-DD> <市场> 第 <N> 次
数据截至：<日期>
| 梗/选题 | 阶段 | 结论 | 用户决定 | 上线日期 | 效果 | 备注 |
|---|---|---|---|---|---|---|
| X 不伤胃 | 衰退 | 跳过 | — | — | — | 功效暗示风险 |
| 万圣节×... | 节点 | 追 | 采用 | 10-31 | 待回填 | |
```

## 读回规则（第 0 步）

- **同一个梗不重复推荐**，除非阶段变了（例如从「等」变成「爆发」），推荐时说明变化
- **用户拒绝过的理由当作约束**：例如"太丧了不要"，就把它写进品牌档案的偏好，后续同类情绪的梗降一档
- **有效果数据就用来校准**：某类梗上线后效果好或差，更新偏好；实际窗口比估计的长或短，在下次估计时提一句
- 用户说"上次那个效果怎么样"时，提醒回填效果列

## 回填

交付后，用户告诉你选了哪几条，就填「用户决定」。上线后用户提供数据（播放、互动、涨粉，或者"效果一般"这样的定性评价），就填「效果」。不要编造效果数据；没有就留「待回填」。
