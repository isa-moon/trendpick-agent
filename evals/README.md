# 评测

三个真实需求，各跑两次：不装 skill（基线）和装 skill（盲测）。按 [rubric.md](rubric.md) 的 12 项打分，通过记 1、部分通过记 0.5。

- **基线**：同一需求、同样的数据工具（热榜 MCP、WebFetch、KOX），不装 skill
- **盲测**：另起一个 Agent，只给它 skill 和需求，不给参考答案，不让它读 `cases/`；跑完后要求它列出 skill 里不清楚、矛盾或只能靠猜的地方
- 星巴克、ROX 在 2026-10-28 跑，数据截至 10-27 / 10-28；安踏在 10-29 跑，数据截至 10-28。安踏的盲测 Agent 是按 README 自己从 GitHub 装的 skill

ROX 的第 6 项（衰退梗不追）不适用，满分按 11 计；扣的 0.5 在第 4 项，海外没有逐日曲线，阶段只能按节点日期和 KOX 发布分布粗判。

安踏基线扣分最多的是第 4、6 项：第一推荐「不烧心」已过峰（逐周 9 → 19 → 20 → 6），第三推荐「闪身步」它自己写了"只剩长尾"，还是推了；阶段只写"连续在榜"和单日峰值。它的黄线识别是满分：烧心的健康联想、+6℃ 的广告法口径、非遗人物肖像、郑钦文是耐克签约、亚运服装是李宁，都写到了。

第 12 项（写入台账）：按测试规则，盲测 Agent 不往用户目录写文件，台账内容写在交付物文末，按"内容完整"计通过。

## 要说清楚的

- **基线并不弱**。不装 skill 的 AI 找热点、写创意都很强：星巴克基线自己找到了骨质疏松传闻和硫磺桂花，ROX 基线找到了胡塞袭击、写出了"脱困小课"。差距在判断：时机、窗口、跳过、出处
- **星巴克盲测有污染**。当时 judgment.md 的举例用的就是星巴克本案，盲测 Agent 自己指出了这一点（见其文末第 1 条）。所以 12 / 12 要打折看。但它也找到了我们自己那版漏掉的东西：两条涉政的星巴克海外条目、涉日民族情绪、「赛车星冰乐」误命中、「X 的含金量」是常驻说法
- **ROX 盲测用的是清理后的 skill**（举例全部换成虚构示意）。它独立发现了沙特的 TikTok 抵制，这是整份方案最重要的结论，我们自己写 skill 时跑的那版（`cases/rox/`）漏了
- 三个案例都没有做社媒饱和度检索（付费工具），"没被做烂"一维偏乐观。安踏盲测的两张卡这一维都是"中（未验证）"，参考内容都是"未找到"
- **安踏盲测 12 / 12，但不是没有问题**：「安踏FILA特步卖不动了」只有 1 条、微博第 214 名，它按当时的字面规则判成"负面发酵中"，整份方案调性降了一档，偏保守。之后补了"零星负面"一档
- 安踏两次运行都是子 Agent，会话里拿不到热点 MCP 工具，两个 Agent 都自己从配置文件读 Key 直连。盲测 Agent 检查配置时还把另一个 MCP 的配置原文打印到了工具输出里（没有进入任何文件）。之后在 sources.md §0 里禁止了这两种做法

## 盲测之后改了什么

**judgment.md**
- 所有星巴克、沙特的举例换成虚构示意
- 新增"查目标平台本身"：平台在当地有抵制、封禁、争议时写在交付物最前面，换平台或只发产品和服务内容
- 竞品范围按用户心里的替代关系定（咖啡 vs 连锁茶饮）；出海品牌也查母品牌的国内舆情
- 宗教节日归类：当地主流宗教的节日是节点（按黄线规则做），其他宗教或外来节日是黄线，拿不准就跳过；宗教讨论是红线
- 单个标题不判阶段，只看簇；节点按日期排期，不看曲线；总条数 < 5 记"样本不足"；"上线周期 = 最早上线日 − 今天"，默认 5 天
- 决策表：产品接得住为弱、品牌又没有机制 → 跳过（之前只能给"等"）；节点的"没被做烂"通常是中，被电商做烂的节点为弱

**sources.md / card-format.md**
- 海外找梗的路径：Know Your Meme 等全球梗 → KOX 在当地验证 → 当地盘点和 X 标签；找不到梗时只出节点和季节，并在结论里写明，不算失败
- 品牌事实可以只有一个来源，标"需品牌确认"
- 阿语内容系统性低估，给出替代渠道（本地团队、X 阿语搜索、Snapchat）
- 海外版卡片模板；KOX 原表放附录，卡片只引关键数字
- K、X 的计数只算"用户可能想追"的条目，其余红线新闻在数据说明里一行带过

**scripts/trend_stage.py**
- 概览和 `--grep` 不再给单个标题判阶段
- 新增 `--show`（代表条目条数）、`--middle`（找"X 在中间"的句式）
- 簇输出逐周曲线；连续 5 周以上每周都有、没有明显峰值的，提示"可能是常驻说法"

**scripts/video_pulse.py**
- `--must` 从子串匹配改成按词边界匹配（`tank` 不再命中 `thank`），`#标签` 只匹配标签
- 分桶按数据跨度自动选周或 4 周，不再丢掉 28 天以上的条目，365 天检索也能看出分布
- 删掉残留的默认品牌词；提示里说明 KOX 按作者去重、品牌号只按作者名识别
- 同形词（hatta 既是地名也是头巾的转写）脚本分不出来，文档要求看头部视频人工剔除

改完后用同一份数据回归：星巴克 9 个簇的阶段（「不烧心」衰退、「可可」顶峰、「冷空气」爆发、「万圣」样本不足等）和改之前的人工判断一致。

## 安踏盲测之后又改了什么

**judgment.md**
- 新增「零星负面」一档：近 7 天只有 1 条、单平台、名次在 50 以外，只避开争议点，整体调性不降
- 品牌正面和负面同时在榜：开头两件都写，各按各的档位处理
- 红线写明包括政治纪念日、重大历史纪念、领导人讣告
- 没有饱和度工具时：先看热榜簇里有没有品牌、平台、电商条目；这一维写「中（未验证）」，不拦推荐，但卡片上写一步上线前自查
- 窗口只在最早上线日成立：记「强（有条件）」，标题写出上线期限和改判日期

**sources.md / card-format.md / SKILL.md**
- §0：检查工具时不打印、不读取 MCP 配置原文；MCP 配了但工具列表里没有，请用户重启或在主会话里跑，不自己读 Key 直连
- 热榜的搜索页链接可以当梗和数据的出处，不能当参考内容
- 国内节点热榜上 0 条时，「为什么是现在」写节点日期、来源和相关季节簇的曲线
- 对齐需求的默认值：推荐最多 5 条，上线周期 5 天

**scripts/trend_stage.py**
- 全是大写的拉丁词（ANTA、FILA）自动区分大小写，不再命中 Fantasy
- 「常驻说法」提示加门槛：总数 ≥ 10、每周中位数 ≥ 2、最近两周没有在涨
- 不到 10 条的簇提示阶段不稳；簇输出前提示品牌、竞品、新闻簇不看阶段
- 0 条命中时提示"节点按日期排期"
- 平台名「哔哩哔哩」统一显示为「B站」

**交付物可读性**：三份盲测交付物的开头都是长段落，括注和链接夹在句子中间，不好读。card-format.md 改成：开头用列表、结论放第一行，推荐卡加「一句话」，括号一句最多一处，出处和链接放句末或附录。

**README**：安装步骤的目标目录改成变量，用户指定了目录就用用户的；加了装完后的验证命令。

用安踏的数据回归：「不烧心」仍判衰退（W3:9 → W2:19 → W1:20 → W0:6），「大结果」仍判爆发，「跑步」「纯过日子」仍提示常驻；「手搓」最近两周在涨，不再提示常驻；`ANTA|安踏` 不再误命中。
